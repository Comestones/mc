# Day 21 协同稳定性与有限负载验收

本目录保存实际运行记录，不是生产容量承诺。执行前先安装 mc_web、mc_sync 的依赖；要求支持原生 TypeScript 的 Node.js（本轮 v24.16.0）。PostgreSQL 使用隔离测试集群，不连接用户数据库。

从仓库根目录：

```powershell
npm --prefix mc_web run verify:day21
npm --prefix mc_web run benchmark:day21
```

verify:day21 运行 3 项真实网络场景及当前 13 项服务端测试，默认不修改已归档报告。benchmark:day21 运行同样的 3 项网络场景并更新 day21-results.json；正常结束的运行会写入通过/失败状态；须同时核对退出码与 recordedAt，若启动失败或被强制终止而未生成新报告，不能沿用旧报告判断本次成功。只有功能断言、SQL 恢复和资源清理全部成功后才记录 passed=true。脚本及重放中继默认只监听 127.0.0.1，不提供公网诊断接口。

## 场景与配置

- 连接握手延迟期间连续 30 次 connect（对应重复 online 事件），只建立一次初始连接；明确断开后仍可重新连接，销毁后无迟到回调。
- 服务不可用时连续 30 次 connect，保留原退避；服务恢复后正常绑定。
- 16 客户端、2 工作区、4 房间（2 页面、2 数据库），合计 280 次页面编辑和 280 次数据库编辑。验证各房间收敛、逐条页面标记不丢失、不重复，数据库不同记录最终值及工作区隔离，页面成员名单按房间隔离。
- 中继保持每个方向的消息顺序，设置 40～119ms 单向应用层延迟；弱网窗口每第 11 条消息丢弃一条，然后恢复转发。保持原连接，等待生产默认 15s state-vector 同步补齐缺失状态。
- 全黑洞期间继续编辑，恢复转发后强制断开旧连接；所有客户端合并恢复。再进行 3 轮全体离线/在线及重复 online 风暴，连接数保持 16、文档数保持 4。
- PostgreSQL 使用默认 500ms 防抖/5000ms 最长等待，查询每房间压缩状态的 Yjs state vector 与所有客户端一致；旧客户端全部销毁后，全新客户端从数据库恢复一致内容。服务连接、房间和中继连接均需归零，服务/数据库必须正常退出。

网络中继模拟的是 WebSocket 应用消息丢失，不是 TCP/IP 丢包模拟器。WebSocket 的 TCP 传输本身会重传丢失数据包；此测试检查更严格的应用消息缺失、延迟与连接中断恢复。单向排队上限 8MiB，中继超限显式关闭连接；本次单方向队列峰值 6530 字节。

使用真实生产 Session、页面/数据库绑定、Awareness、Hocuspocus 和 pg 存储。为缩短测试，重试退避是 50～200ms、关闭随机抖动；生产仍保持 1～30s 指数退避与抖动。15s 同步周期、45s watchdog 和服务端写入防抖保持生产默认。测试不加载客户端 IndexedDB；关闭重开的完整 CRDT 缓存仍由 verify:day20 独立覆盖。

## 本轮实测

环境：win32/x64，AMD Ryzen 5 5600 6-Core Processor，12 个逻辑 CPU，Node.js v24.16.0，PostgreSQL 18.4；原始 UTC 时间 2026-10-23T12:08:44.325Z。源码文件字节 SHA-256 和固定故障随机种子写在 JSON 中，便于核查被测实现。

| 基线远端传播样本 | 480 |
| 基线 p50 / p95 | 68.85 / 104.37 ms |
| 基线全体最终收敛 | 126 ms |
| 弱网传播样本 | 240 |
| 弱网 p50 / p95 | 15043.58 / 15171.39 ms |
| 结束丢帧后完整修复 | 13715 ms |

| 中继显式丢弃消息 | 118（含全黑洞阶段） |
| 最终连接 / 房间 / 中继连接 | 0 / 0 / 0 |

传播延迟从生产者本地编辑发起计时，到其他同房间客户端投影包含该唯一标记；p50/p95 只统计页面文字标记，不把数据库的原子覆盖中间值当作必须逐条送达的消息。基线 160 次页面编辑对应其他 3 个同房间接收者，共 480 份样本；弱网 80 次页面编辑共 240 份。结束丢帧后的修复时间从停止丢帧开始计时，弱网传播延迟则从原始编辑发起计时。

服务 RSS 在重连前/后/清理时分别为 70.77 / 75.65 / 75.66 MiB；事件循环采样 p95 约 16.06ms（采样分辨率 10ms）。RSS 不要求回落到起点，不能用本轮有限观测证明长期无内存泄漏；本轮明确验证的是连接、文档和自有进程正确释放。该负载不包含公网、浏览器 DOM 渲染、长期浸泡或容量上限测试。
